# 分镜素材策略：机器人怎么"看见"世界？

用途：生图前的把关闸门。每个分镜先判定素材方式，再进入对应工步；禁止默认全部生图。

## 判定规则

1. **模型生图**只用于"真实场景 + 角色一致性"的镜头：机器人本体必须准确还原 OW12-300 外观，且画面是物理场景而非概念。
2. **Python 绘制**用于原理、概念、信息流类画面：几何关系和信息结构必须准确，生图几乎必然出错（假文字、乱标注、几何错误），代码绘制可精确控制且风格可复用。
3. **真实素材**优先复用已有官方参考图：特写类镜头如果参考图里已有高质量画面，裁剪即可，不生图。
4. 互联网图片**默认不用**（版权与画风不统一）；确需使用时必须标注来源与授权，写进事实核验说明。03 视差图曾评估过维基共享资源的 CC 候选图，因白底英文教科书风格与全片冲突，最终决定 Python 重绘。
5. 所有素材遵守同一视觉规范：洁净室浅色/深蓝氛围、克制的橙色高光、画面无可读文字。
6. 同一分镜生图不超过 3 次：仍不通过则改用 Python 绘制或真实素材，避免抽卡浪费。

## 逐镜分流

| 分镜 | 素材方式 | 理由 | 把关要点 |
|------|----------|------|----------|
| 01 开场：先回答我在哪 | 生图 | 主角首次亮相定调，需要"静立环顾"的干净全景，参考图中没有 | 外观对照 5 张参考图；灯带、传感器窗口位置准确 |
| 02 摄像头：主感官 | 真实素材裁剪 | 传感器与机械臂特写在官方图中已是高质量实拍，生图反而会在镜头数量、标识位置上出错 | 裁剪区域需避开参考图中的水印与英文字条；可用区域分辨率须够 1920×1080 |
| 03 双目：像人眼一样测距 | 真实素材处理 | 避障演示实图（机器人正对交通锥）比抽象示意图更有说服力；原 Python 视差示意图方案已弃用 | 由 `work/draw_diagrams.py` 从 `assets/优艾智合-避障演示.png` 裁剪修补：去水印、丝印与贴纸，保留机器人与锥桶对视构图 |
| 04 激光雷达：主动发光测距 | 生图为主，点云可用 Python 叠加 | 机器人主体需生图；点云若生图易变成屏幕图形，更稳的做法是 Python 生成贴合墙面轮廓的点阵叠加 | MVP 先纯生图，审核点云是否像物理光影；不像则改叠加方案 |
| 05 多传感器融合 | Python 绘制 | "融合"是信息流概念，生图只能表达"灯都亮了"，意图必然偏离；框图更准确 | 只保留 2~3 个传感器输入和 1 个世界模型输出，不堆术语 |
| 06 从像素到语义 | Python 绘制（自有图叠加） | 像素到物体的识别过程是经典示意场景，生图会生成假文字与乱标注；现成分割示例图（Cityscapes 等）授权偏研究用途且场景不相关 | 以自有生图或参考图为底，用色块高亮表达"认出物体"，不得出现可读文字 |
| 07 实时性与算力 | Python 绘制 | RK3588 嵌入式计算板与传感器/外设连接关系需要准确表达，生图容易画错接口与主体比例 | 中央仅保留 RK3588 型号文字；摄像头、激光雷达、深度感知、机械臂、网络、供电均以图标表示 |
| 08 失效与自知 | 生图 | 黄光区眩光 + 减速停车的氛围镜头，真实素材不存在 | 情绪表达：姿态收敛、灯带变暗，而非故障报警感 |
| 09 系统工程结论 | 生图 | 抽象收束镜头，定调整条片子的结尾质感 | 点云克制、背影构图、与 01 开场呼应 |

汇总：生图 4 张（01、04、08、09），真实素材处理 2 张（02 裁剪、03 裁剪+去水印修补），Python 绘制 3 张（05、06、07）。02/03/05/06/07 均由 `work/draw_diagrams.py` 幂等产出。
