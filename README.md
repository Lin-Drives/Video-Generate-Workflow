# 机器人工程解读视频 MVP

MVP 是 **Minimum Viable Product（最小可行产品）**。在本项目中，它指可实际产出并验收一条完整视频的最小版本：跑通“分镜、配音、字幕、渲染与验收”这条生产链路，后续再逐步扩展选题、资产和自动化能力。当前 MVP 的验收时长为**单条 1～2 分钟**（含片头片尾）；超出这个范围时，应拆分选题或另行调整脚本与分镜，而不是默认拉长口播。

本地生成中文横版 YouTube 视频：口播稿/分镜 → Edge TTS 配音 → 字幕 → 图解卡片 → MP4。

## 运行环境与工具

- **macOS**：本项目在 Mac 本地运行与管理素材。
- **FFmpeg CLI**：通过命令行完成图片、配音、字幕、片头片尾的合成与 MP4 导出；无需依赖图形化剪辑软件完成基础渲染。
- **Codex**：用于协作编写和维护脚本、审核资产与字幕规则、执行渲染验证，并沉淀可复用的制作经验。

## 工作流总览

```mermaid
flowchart LR
    A[选题与口播稿] --> B[分镜提示词]
    B --> B0[素材方式评审<br/>生图/真实素材/Python]
    B0 --> C{生图与人工审核}
    C -->|GPT 主流程| D[GPT 分镜资产<br/>assets/gpt5.6]
    C -->|必要时 Qwen 备选| E[Qwen 分镜资产<br/>work/build]
    D --> F[配音与双语字幕]
    E --> F
    F --> G[FFmpeg 渲染<br/>片头 正文 片尾]
    G --> H[验收<br/>时长 1～2 分钟<br/>音画 字幕 分辨率]
    H --> I[输出 MP4 与 SRT]
    I --> J[剪辑软件二次编辑<br/>或修改源资产后重渲染]
```

分镜提示词定稿后、生图开始前，先按 `outputs/分镜素材策略-*.md` 评审每个分镜的素材方式：真实场景且要求角色一致的才生图，原理与概念画面优先 Python 绘制，已有高质量官方素材的直接裁剪复用；互联网图片默认不用。避免全部分镜一股脑生图造成的重复、意图偏离与观感疲劳。

## 使用

```bash
./render.sh
```

产物在 `outputs/`：视频、SRT 字幕、封面 PNG、标题草案和事实核验说明。

## 二次编辑

导出的 MP4 可直接导入 Final Cut Pro、DaVinci Resolve、Premiere 等剪辑软件，进行裁切、调色、加配乐和叠加图层；但它是已合成的成片，画面、配音和烧录字幕不再是可单独调整的轨道。

需要改文案、镜头、字幕或配音时，应编辑项目中的源资产后重新渲染：`assets/ow12/` 保存本片审核后的分镜图，`work/build/*.mp3` 保存配音，`outputs/*.srt` 保存可编辑的双语字幕，`work/generate.py` 保存时间轴、字幕与合成逻辑。若在剪辑软件中改动时长，还需同步校正 SRT 时间轴。

配音默认使用 Edge TTS；如需更换音色，可在当前终端设置 `TTS_VOICE`，无需将密钥写入项目文件。

## GPT 生图主配置

默认主配置为 GPT 生图：先依据 `outputs/分镜提示词-感知与视觉.md` 生成、审核分镜，再将通过审核的图片保存到 `assets/ow12/`，随后渲染：

```bash
REUSE_AUDIO=1 USE_EXISTING_IMAGES=1 ./render.sh
```

GPT 分镜必须以角色参考图为准。对于跑步、冲刺、上坡等动态姿态，需同时检查：对侧臂腿反向摆动、躯干不过度前倾、高髋、细长连杆腿比例；单帧好看不等于动作正确。

经验记录：文生图对跑姿的运动学一致性仍有随机性，不能把一次生成当作事实正确。动态镜头必须经人工审核；若需要严格、可复现的步态，应改用骨骼动画或三维动画后再渲染，而不是反复抽图。

图片、配音均已生成但只需重新封装视频或验证 IINA 字幕时，可复用本地素材而不调用 API：

```bash
REUSE_AUDIO=1 USE_EXISTING_IMAGES=1 ./render.sh
```

字幕会以与视频同名的 `.srt` 文件导出，IINA 会自动加载；若未自动加载，可在 IINA 的“字幕”菜单中选择该文件。

视频同时会直接烧录字幕，播放器无需加载字幕轨。分镜图需先经 GPT 图像工作流生成并审核，再替换到 `assets/ow12/` 后重新渲染。

## 字幕制作规范（已验证）

当前脚本将字幕直接烧录到画面，并同步导出可编辑的双语 SRT。后续视频应复用以下规则：

- 断句以完整问句、句子或意群为优先；仅当单条超过约两行的舒适阅读长度时，再在逗号或分号处拆分。不得留下“母线”“持续”等孤立词。
- 中文使用 `/System/Library/Fonts/Hiragino Sans GB.ttc` 的 W6 字重；不要回退到 `STHeiti`，以避免简体中文字形和中文标点异常。
- 保留句内中文标点以维持语义；屏幕显示和 SRT 中均移除每条字幕末尾的标点。
- 英文逐条对应中文意群，置于中文正下方，字号小于中文；不单独按英文长度重新分段，以免与中文和口播错位。
- 完成渲染后，必须用 `ffprobe` 核验视频、音频、分辨率和时长，并在至少两个不同段落抽帧检查中文、中文标点、英文、行距和画面遮挡。

仅复用已有配音与分镜、导出带双语字幕的新版本，例如：

```bash
REUSE_AUDIO=1 USE_EXISTING_IMAGES=1 OUTPUT_BASENAME='机器人冲刺的那几秒-中英字幕版' ./render.sh
```

## 片头与片尾（已验证）

渲染脚本会自动在正片前后加入片头和片尾，均复用项目现有的分镜图，不依赖外部下载资源：

- 片头：复用 `01-开场冲刺.png`，3.5 秒淡入推近，显示中英双语标题。
- 片尾：复用 `09-系统工程结论.png`，5 秒淡出，显示系统工程结论与关注 CTA。
- 片头与片尾均带静音 AAC 音轨，保证可以和正片的配音片段无缝拼接；SRT 时间轴从片头结束后开始。
