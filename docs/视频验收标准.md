# 视频任务与验收标准

## 1. 适用范围与完成条件

本标准适用于本项目的机器人解读视频。用户明确指定的任务要求优先于默认值。

Agent 接到任务后，应自行完成制作、检查、修复和复验。每轮修改无需用户检查。只有全部必检项通过、交付文件齐全且没有待人工确认项时，才能声明“验收通过”。生成文件、渲染成功、抽帧正常均只是中间结果。

本文件规定执行流程。目前 `render.sh` 仅输出媒体参数，完整解码、音频检查、逐镜头检查和验收报告仍需 agent 主动执行。

## 2. 开始前形成任务约定

优先复用用户已确认的脚本、角色参考、风格和术语表。未指定项采用下列默认值，并在验收报告记录。仅缺少会影响正确性、授权或核心方向的信息时，集中询问一次，其余环节继续执行可独立完成的工作。

| 项目 | 默认要求 |
| --- | --- |
| 交付类型 | 本地可播放成片、同名双语 SRT、验收报告 |
| 内容与观众 | 机器人科普，沿用当前任务的选题与已确认文案 |
| 视频规格 | 横版 1920×1080、30 fps、H.264、yuv420p、AAC，含音轨 |
| 时长 | 完整成片 60～120 秒，含片头片尾 |
| 字幕 | 中文在上、英文在下，遵循 README 字幕规范 |
| 风格与配音 | 复用已确认样片、角色参考及当前配音配置 |
| 修改范围 | 仅修改任务相关资产，保留用户已有修改与源文件 |
| 外部成本 | 只使用已获授权的服务与额度，未授权的付费调用需确认 |

不同项目的录屏、宣传片或短片，应按该任务明确的时长和规格验收。不能直接套用本项目的 60～120 秒。

新选题须先执行 [新选题制作流程](新选题制作流程.md)，通过正式剪辑准入检查后再进入成片制作。准备阶段的通过记录与最终验收报告相互关联。

## 3. 哪些任务可交给 agent

“可独立完成”以输入可用、工具可用且必要授权齐全为前提。

| 任务 | 自主程度 | 完成边界 |
| --- | --- | --- |
| 使用已确认脚本、素材和模板制作成片 | 可独立完成 | 配音、字幕、合成、检查、修复、复验及交付 |
| 改错字、调整字幕布局、修复音画错位、替换已指定素材 | 可独立完成 | 保持原意，复验受影响片段及成片技术完整性 |
| 已确认方向内的图解卡片、封面排版、转场与节奏调整 | 可独立完成 | 有参考和验收条件，完成视觉自检 |
| 公开事实核查、资料整理、脚本和分镜初稿 | 可独立完成对应草稿 | 引用可追溯来源，未证实内容删除、弱化或列为待确认 |
| 新选题的研究与制作准备 | 可独立完成 | 建立制作包并通过剪辑准入检查，核心方向有歧义或用户要求先审时集中确认 |
| 新审美、首次音色、品牌表达 | 先确认一次方向 | 先交短样片或关键帧，确认后按同一标准批量制作 |
| 真实机器人跑步、冲刺、上坡等生成画面 | 保留人工确认 | Agent 先检查结构、姿态与参考一致性，再提交具体镜头供确认 |
| 严格可复现的步态演示 | 采用可验证动画流程 | 使用骨骼或三维动画，建立运动学标准后验收；单张生图不能证明步态正确 |
| 素材使用权不明、核心事实矛盾 | 需要决策 | 优先寻找有明确许可的替代素材或可靠来源，无法解决时集中提问 |
| 发布、付费购买、外部发送 | 按用户授权执行 | 制作阶段先完成可交付结果，发布动作遵循明确授权 |

已确认的样片可作为后续任务基准。主观审美有分歧时，应将反馈转为可执行规则，例如主体占画面比例、标题长度、转场时长，再用于后续自检。

## 4. 必检项与证据

### A. 内容与素材

- 每个镜头对应一个明确的信息点，画面与该段口播一致。
- 数字、单位、专有名词、产品能力和因果结论逐项核对。关键事实记录来源，演示图与实拍素材标明性质，不能把示意画面当作真实测试证据。
- 逐镜头检查角色外形、肢体数量、机械连接和图解方向，避免镜像文字、结构变形和错误运动暗示。
- 记录外部素材出处及使用依据。来源或权利无法确认的素材不能默认进入可发布成片。

### B. 成片技术完整性

- 用 `ffprobe` 检查实际视频流、音频流、编码、像素格式、分辨率、帧率和完整成片时长，逐项对照任务约定。
- 对最终 MP4 完整解码，退出成功且无解码错误。报告保存执行结果，不能只检查文件存在或读取片头。
- 检查黑场、静帧与静音的时间区间。按分镜判断是否属于设计内容，图解静帧和片头片尾静音可以保留，正文意外黑场、卡住或缺失配音必须修复。
- 完整播放最终文件，确认首尾、拼接处和最后一句完整，无意外截断。

参考命令，执行时替换为本次成片路径并保留输出。

```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,pix_fmt,r_frame_rate -of json "$VIDEO"
ffmpeg -v error -xerror -i "$VIDEO" -f null -
```

### C. 配音与声音

- 核对完整配音与最终脚本，确认无漏句、重复、错序。可用转写辅助比对，疑似错误必须回听，尤其是数字、单位和专有名词。
- 每个镜头至少回听一次，覆盖全部口播。检查读音、句间停顿、剪接处爆音、截字、明显音量跳变及背景音遮挡。
- 用音频分析检查电平和异常静音，听检确认无削波失真、正文意外断音。任务要求平台响度时，测量并对照该目标。
- 若工具无法播放或理解音频，报告标记“待确认”，不能根据波形或转写直接判定听感通过。

### D. 字幕与画面

- 校验全部 SRT 条目，时间戳递增、结束晚于开始、无非设计重叠、无越过片长，中英对应且与最终脚本一致。
- 检查全部字幕渲染画面，可复用未变化的字幕布局逐条检查。确认中文字体、标点、英文、换行和行距，无乱码、溢出和遮挡关键信息。
- 字幕与口播对应意群的起止偏差默认不超过 0.3 秒。分段停顿允许延长停留，但不得跨入下一段不相关口播。
- 每个镜头至少检查一张代表帧，所有转场检查切点前后画面。标题、字幕最长处、插片标签和片尾必须单独检查。
- 对运动镜头、推拉和转场播放完整片段，确认无跳变、闪烁、错误裁切和不合理动作。静态抽帧仅能证明画面布局。
- 正文有效内容与文字默认距画面边缘至少 5%，有意满版的背景除外。沿用已确认布局时记录依据。

### E. 交付与回归

- 最终 MP4、同名 SRT 和验收报告使用相同版本标识。报告写明文件路径及 SHA-256，确保检查对象就是交付对象。
- 修改字幕需复验全部受影响字幕及相邻切点，修改配音需复验对应口播及后续时间轴，修改时间轴需复验全部受影响镜头。
- 最后一次修改后，对最终文件重新执行技术完整性检查。先前版本的结果不能替代最终版本的验收证据。
- 修改代码后按项目规范先验证，再对完成的独立模块创建本地 Git 提交，记录实际验证结果。

## 5. 失败处理与停止条件

1. 发现不合格项后，定位具体镜头、时间码和原因，优先局部修复，再复验。
2. 同一问题默认最多自主修复三轮。无法解决时整理尝试、证据和可选方案，集中请求需要的决定，避免无目标重试。
3. 缺少工具时先尝试现有工具或可行替代方式。必检项无法执行时，将该项保留为待确认。
4. 参数不符、解码错误、错字漏句、素材缺失和明显画面错误属于必须修复项。风格偏好只有在违背任务约定或已确认样片时才判失败。
5. 待人工确认镜头可集中形成一份审阅包，附时间码、画面与具体问题。其余已授权工作继续完成。

交付状态只使用以下三种。

- **验收通过**。全部必检项通过，所需人工确认已完成，可按约定交付。
- **待确认**。存在需要用户判断或暂时无法验证的项目，明确列出剩余项。
- **未通过**。存在已确认缺陷，说明修复状态及阻碍。

## 6. 验收报告最小格式

每次交付保存 `outputs/<成片名>-验收报告.md`，至少包含以下内容。

- 任务约定、采用的默认值、使用的已确认参考。新选题附制作包路径和剪辑准入记录。
- 最终文件路径、版本和 SHA-256。
- 内容、技术、配音、字幕画面、交付五类检查的逐项结果，使用“通过／未通过／待确认／不适用”，不适用项说明理由。
- 检查方法、实际测量结果、证据文件或时间码。未执行项写明未执行及原因。
- 已修复问题和复验结果。
- 人工确认记录或待确认问题。
- 最终状态，及代码变更对应的本地提交信息。

## 7. 可直接使用的任务下达方式

> 按《视频验收标准》完成本次视频。选题为……，使用脚本……、素材……、参考样片……。未指定项使用项目默认值。请自行制作、检查、修复和复验，交付最终 MP4、同名双语 SRT 和验收报告。只有方向、授权或规定保留人工确认的事项需要集中询问，其余问题自行处理。若无法通过验收，列明具体缺陷、时间码和已尝试方案。
